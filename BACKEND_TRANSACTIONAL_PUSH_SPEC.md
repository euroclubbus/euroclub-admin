# Транзакційні (сервісні) push-сповіщення — технічний опис для прогера

## Контекст

У панелі керування (адмінка) EuroClub тепер є два типи сповіщень:
- **Маркетингові** — акції, новини, загальні розсилки. Надсилаються вручну через адмінку.
- **Сервісні (транзакційні)** — пов'язані з конкретним замовленням/рейсом юзера
  (наприклад: "Оплату отримано", "До відправлення вашого рейсу лишилось 2 години",
  "Статус замовлення змінено"). Позначаються червоною міткою в застосунку.

**Зараз** сервісні сповіщення можна надіслати **тільки вручну** через адмінку (Кеп заходить
і сам пише текст). **Хочемо додати** можливість, щоб **бекенд сам** ініціював такі
сповіщення автоматично, коли відбувається відповідна подія (оплата пройшла, наближається
час відправлення тощо) — без участі людини.

## Що потрібно від бекенду

Коли на бекенді стається подія, яка має призвести до сповіщення юзера (оплата, зміна
статусу, нагадування про рейс тощо) — бекенд робить **один HTTP-запит** до нашого
адмін-API:

```
POST https://euroclub-admin.vercel.app/api/send-push
Content-Type: application/json

{
  "title": "Оплату отримано",
  "body": "Дякуємо! Ваше замовлення №1029795 оплачено.",
  "userIds": ["187728"],
  "type": "service"
}
```

**Поля:**
- `title` (обов'язкове) — заголовок сповіщення
- `body` (обов'язкове) — текст
- `userIds` (обов'язкове для точкового сповіщення) — масив id юзера/юзерів, кому надіслати
  (той самий `user_id`, що повертається в `user-orders`)
- `type` — `"service"` для транзакційних (обов'язково вказувати, інакше піде як
  `"marketing"` за замовчуванням)
- `deepLink` (необов'язково) — посилання, куди веде тап по сповіщенню (напр.
  `euroclub://orders/1029795`)

**Що відбувається на нашому боці:**
1. Запис **завжди** додається в "папку сповіщень" юзера в застосунку (`notifications/{userId}/messages`) — юзер побачить його, коли зайде в "Мої сповіщення", незалежно від того, чи ввімкнені в нього push
2. **Якщо** у юзера є зареєстрований push-токен (дав дозвіл на сповіщення) — **додатково**
   прилітає банер на екран телефону

**Відповідь:**
```json
{ "targetCount": 1, "successCount": 1, "status": "sent" }
```

## Захист ендпоінту

Наразі цей ендпоінт **не має** окремого секретного ключа для зовнішніх викликів (захищений
лише тим, що URL не публічний). **Якщо бекенд буде викликати це регулярно й автоматично —
потрібно домовитись про API-ключ**, щоб цей вхід не був відкритий для будь-кого, хто дізнається URL. Це нескладна доробка з нашого боку — просто дайте знати, коли будете готові
інтегрувати, і ми додамо перевірку ключа.

## Приклади подій, де це може стати в пригоді

- Оплата підтверджена (webhook від LiqPay/Stripe)
- Замовлення скасовано з боку компанії
- Наближається час відправлення (напр. за 2-3 години до рейсу)
- Зміна статусу замовлення (затримка автобуса, зміна платформи тощо)
